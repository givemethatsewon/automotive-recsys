## 원문·후속 요구·실행의 관계

1. 제안서는 프로젝트 전체의 RQ1–RQ4와 계획을 제공한다. 가설을 검증 결과로 취급하지 않는다.
2. Notion 개요는 박신빈의 Spark 전처리, 민세원의 모델 학습·평가 역할을 명시한다. 회의 전사의 잘못 인식된 이름으로 역할을 바꾸지 않는다.
3. 사용자는 이후 Popularity 별도 기준선, 대조학습 고려, Colab GPU, 3 seeds, Drive 저장·진행 로그·자동 복구를 명시했다. [후속 요구](sources/conversation-decisions.md)를 함께 읽는다.
4. 실제 입력 규모·마스킹·모델 설정·완료 여부는 실행 manifest와 [최종 결과](RESULTS_FINAL.md)로 확인한다. 원문에서 언급한 대략적인 수치나 예상 순위를 실제 실험 결과로 쓰지 않는다.

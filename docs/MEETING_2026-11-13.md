## 회의 설명에서 바로잡을 부분

- **100/500은 사용자 표본 수가 아니라 사용자당 재정렬 후보 상품 수**다. 기존 후보 진단은 valid 220,516명 전체에서 top100/500/1000을 비교했다. 기본 학습 데이터가 100/500개였던 것이 아니다.
- **기존 차종 실험에 차종 노드·엣지 추가나 재학습은 없었다.** 사용자–상품 그래프와 checkpoint를 유지한 뒤, 차종 일치 상품의 추천 점수에 가점을 줬다. 스크립트 16:07의 ‘차종 노드 추가’에 대한 동의는 실제 구현 설명으로 사용하지 않는다.
- 회의의 BPR-MF ‘약 12%’는 [후보 진단](CANDIDATE_DIAGNOSTIC_2026-11-11.md)의 **seed42, 후보500, valid 탐색 +12.12%**와 연결된다. 같은 진단의 LightGCN은 +1.98%, XSimGCL은 +0.71%였다. test·3-seed 확정 개선이나 ‘그래프 모델 성능 저하’로 바꿔 쓰지 않는다. 별도 pool500 test 파일럿의 BPR-MF +5.82%와도 구분한다.
- 같은 입력·학습 recipe·seed로 기본 모델만 재실행하면 v2 파일을 읽지 않는 기존 학습기에는 차종 효과가 들어가지 않는다. 회의가 요구한 학습 단계 비교를 수행하려면 차종을 학습에 연결하는 방식을 먼저 명시해야 한다. 재학습은 합의됐지만 차종 노드 추가·loss 변경 같은 구체 방식은 확정되지 않았다.

## 수령한 v2와 남은 의존성

Notion의 기존 vehicles 링크는 취소선이고 v2가 새 링크다. v2에는 `product_fitment.parquet`, A1/A2의 valid용·test용 총 5개 Parquet, `code/vehicle_fit.py`, 검수·사전·근거 폴더가 있다. [파일 목록](sources/vehicles-v2-inventory-2026-11-17.json)은 메타데이터 조회 결과이며 Parquet를 내려받아 hash/행 수/시점을 검증했다는 뜻이 아니다.

- 변경: Lexus 숫자 모델/Econoline 등 사전 보강, 두 자리 연식·나열·열린 범위 처리, 상품별 여러 차종에 연식 연결, 제조사 수 대신 계열 수로 범용 판정, E-Series 별칭. 이들은 입력 변경과 매칭 규칙 변경으로 나눠 비교한다.
- 검수: README 11절은 **Claude(Sonnet) 판정 + 일부 사람 확인**이다. 상품·사용자 각 100개 v3 샘플이며 전수 사람 검수가 아니다. 상품 완전 정답 77/100, 사용자 정답 89/100이라는 출처 보고값을 모델 재실험 결과로 표시하지 않는다. v2 검수는 규칙 튜닝에 쓰였으므로 v3 정확도와 직접 전후 비교하지 않는다.
- 최신 인수인계는 재정렬을 제안하고 ‘모델 학습·평가 완료’라고 적는다. 이는 11/13의 재학습 합의를 취소했다는 근거가 아니다. 원문 제안과 회의 결정의 서로 다른 범위를 유지한다.
- 텍스트 γ는 후보 쌍을 전달하면 전처리 담당이 계산할 예정이라고 적혀 있다. 아직 특징 파일을 수령한 것은 아니다. 실제 구매 리뷰를 회원정보로 쓰는 시나리오도 제안일 뿐이며 주 평가에 포함하지 않는다.
- Spark 폴더에 `rq1_stats.json`, `timing.csv`가 있는 것을 확인했다. 자료 미존재 상태가 아니라 **내용·코드·입력과의 대응 검토가 남은 상태**다.

원문·스냅샷·보존 방식은 [출처 안내](sources/README.md), 다음 실행 조건은 [v2 계획](VEHICLES_V2_PLAN.md)을 따른다. 발표 자료는 기존 본실험 → 차종 v1 후보 병목 → v2 클리닝 변경 → 같은 조건 비교 → 원인·한계 순서로 구성한다. 새 실험 결과가 나오기 전에는 개선 수치나 재학습 완료를 추가하지 않는다.

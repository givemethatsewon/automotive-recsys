## 2. 사용법

```python
import sys; sys.path.append("/content/drive/MyDrive/빅데이터 팀플/vehicles/v2/code")   # v2 안의 코드 사용
from vehicle_fit import VehicleFit, load_vehicles

vf = VehicleFit(user_vehicles=load_vehicles("both", until="valid", min_items=2))   # 튜닝
# vf = VehicleFit(user_vehicles=load_vehicles("both", until="test", min_items=2))  # 마지막 테스트

# β: 후보 top-100에 fit 열(1 맞음 / -1 안 맞음 / 0 모름)이 붙음
cand = vf.fit_status(cand[["uid", "iid"]])
# 최종 점수 = 모델 점수 − λ·인기도 + γ·텍스트 유사도 + β·(fit == 1)

# Mismatch@10: recs는 uid, iid, rank(1부터)
res = vf.mismatch_at_k(recs, k=10, user_groups=user_map.set_index("uid")["group"])
res["summary"], res["by_group"], res["per_user"]
```

### 출력 예시

검증용 파일(`until="valid"`)로 실제로 돌린 결과입니다.

**`fit_status()`**: 넣은 표에 `fit` 열만 붙어서 나옵니다. 이 열을 β 가점에 씁니다.

```
   uid    iid  fit
     1 228482    0     ← 판단 불가 (차종 정보 없음)
     1   2916    0
     1 226085    1     ← 이 사용자 차에 맞는 상품 (-1이면 안 맞음)
```

실제 검증 구매 515,201건 기준 분포는 1(맞음) 8.8% / -1(안 맞음) 10.5% / 0(모름) 80.6%입니다. 대부분 0이라서 β는 일부 후보의 순서만 바꿉니다.

**`mismatch_at_k()`**: 지표가 담긴 딕셔너리가 나옵니다. 아래는 실제 검증 구매를 추천 목록처럼 넣은 결과로, 그대로 **실제 구매 기준선**이 됩니다.

```
res["summary"]
  users: 134,809                        ← 차종을 아는 사용자만 평가
  mismatch@k: 0.0392  [0.0388, 0.0396]  ← 상위 10개 중 안 맞는 비율 (95% 신뢰구간)
  match@k: 0.0328                       ← 상위 10개 중 맞는 비율
  fit_known@k: 0.0720                   ← 상위 10개 중 판정 가능한 비율
  mismatch_among_known: 0.549  [0.546, 0.553]  ← 판정 가능한 것 중 안 맞는 비율

res["by_group"]                         ← 같은 지표를 그룹별로 (RQ3용)
  1-5 : mismatch_among_known 0.604  (52,033명)
  6+  : mismatch_among_known 0.515  (82,776명)

res["per_user"]                         ← 사용자별 표 (부트스트랩 등 추가 분석용)
  uid  n_mis  n_match  n_known  mismatch@k  match@k  fit_known@k  mismatch_among_known
```

- 모델 추천의 `mismatch_among_known`이 0.549보다 높으면, 실제 사람이 사는 것보다 차에 안 맞는 부품을 더 추천한다는 뜻입니다. β를 걸면 이 값이 내려가야 합니다.
- 위 예시의 `mismatch@k`는 실제 구매가 사용자당 10개보다 적어서 낮게 나왔습니다. 모델 추천은 항상 10개라서 이 문제가 없습니다. 다만 차종 정보가 있는 상품이 적어서 `mismatch@k`는 원래 작게 나오는 지표이니, `mismatch_among_known`과 함께 보고해 주세요.
- 부트스트랩 기본값(`n_boot=1000`)은 메모리를 1~2GB 씁니다. 부족하면 `n_boot=500`으로 줄이면 됩니다.

### 옵션

- 첫 인자: `"text"`(A1) / `"items"`(A2) / `"both"`(A1+A2, 기본 추천)
- `VehicleFit(..., level="make")`: 제조사 단위로만 비교
- 테스트 사용자 전체 계산에 10초 안팎

**"맞음" 판단**: 제조사가 같고, 자동차/오토바이가 섞이지 않고, 모델은 둘 다 알 때만 비교합니다(Civic = Civic Si, Dodge Ram = Ram 1500처럼 이름 차이는 정리함). 연식은 둘 다 알 때만 비교합니다. 사용자 차가 여러 대면 하나라도 맞으면 맞음이고, 범용 상품은 "모름"입니다.

## 3. 결과 해석할 때 꼭 알 것

테스트 기간에 실제로 산 상품이 사용자 차와 얼마나 맞는지 쟀습니다(`vehicle_source_comparison.csv`).

| 차종 출처 (테스트 시점) | 테스트 사용자 커버리지 | 실제 구매와 맞는 비율 | 랜덤 상품 |
| --- | --- | --- | --- |
| A1 리뷰 본문 | 54.1% | 36.7% | 5.1% |
| A2 구매 상품 (2개 이상) | 41.3% | 47.7% | 9.2% |
| **A1 + A2 (기본 설정)** | **67.5%** | **46.2%** | 8.3% |

(맞는 비율은 모델 단위 기준. 11-10 버전은 각각 39.0 / 48.8 / 47.4%였는데, 차종 추출이 나빠진 게 아니라 범용 기준이 바뀌어 예전엔 "모름"이던 상품 약 2,700쌍이 판정 대상에 들어온 영향입니다. README 10절)

- 실제 구매는 랜덤보다 5~7배 잘 맞습니다. 차종 정보는 쓸모가 있습니다.
- 그래도 **실제 구매의 절반 정도가 "안 맞음"**으로 나옵니다(차가 여러 대, 차를 바꿈, 가족 차). 그래서 Mismatch@10은 **실제 구매의 Mismatch(검증 0.549, 2절)를 기준선으로 함께** 보고해 주세요.
- Mismatch는 β에 쓴 차종 정보로 계산하므로 β를 키우면 당연히 낮아집니다. 차종 정보의 실제 효과는 **NDCG@10이 오르는지**로 판단합니다.
- 차종을 모르는 사용자(테스트 사용자의 약 32.5%)는 β가 0이라 결과가 그대로입니다. β 효과는 **차종을 아는/모르는 사용자로 나눠서** 보고해 주세요.

## 4. 실험 순서 (제안)

후보는 **XSimGCL**(정확도 1위)과 **LightGCN**(비인기 노출 1위)의 top-100입니다.

| 비교 | 대조군 | 실험군 | 판단 지표 |
| --- | --- | --- | --- |
| 다양성만 높이면 안 맞는 부품이 늘어나나 | 원래 모델 | λ, λ+γ | Mismatch@10 (+ 실제 구매 기준선) |
| 차종 정보가 정확도를 올리나 | λ+γ | λ+γ+β | **NDCG@10** |
| (추가) 출처 비교 | — | β를 A1 / A2 / A1+A2로 | NDCG@10 |
| (추가) 비교 단위 | — | β를 모델 / 제조사 단위로 | NDCG@10 |

γ(텍스트 유사도)는 A가 후보 top-100 쌍에 대해 계산해서 줄 예정입니다. 후보 파일이 나오면 공유해 주세요.

## 5. 같이 정해야 할 것

1. **β 비교 단위**: 모델 단위, 제조사 단위, 또는 둘 다
2. **"회원정보가 최신일 때" 시나리오 추가 여부**: 테스트 구매 리뷰에 적힌 차("Bought for a 2014 Tacoma")를 회원정보로 보고 평가하는 방식입니다. 결과가 다소 낙관적으로 나옵니다. 하기로 하면 A가 추출합니다.
3. **Mismatch@10 보고 방식**: 실제 구매 기준선과 함께 볼지, 제조사 단위를 주 지표로 쓸지

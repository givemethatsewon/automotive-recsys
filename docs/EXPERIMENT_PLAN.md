## 2. 선정 모델: 학습 3개 + 비학습 기준선

### Popularity: 비개인화 기준선

학습 기간의 상품별 상호작용 수 내림차순. 동점은 iid 오름차순.
사용자의 과거 상품을 제외하는 것 외에는 개인화하지 않는다.
사용자의 요청대로 정식 기준선으로 결과표에 포함한다.

### BPR-MF: 개인화 기준선

사용자·상품 벡터의 내적으로 점수를 계산하고 BPR 목적함수로 학습한다.
관측된 상품이 학습 기간에 관측되지 않은 상품보다 높은 점수를 받도록 학습한다.
관측되지 않은 상품을 사용자가 싫어했다는 사실로 취급하지 않는다.
그래프 전파 없이 취향을 학습하는 기준을 제공한다.

### LightGCN: 그래프 효과 비교

학습 상호작용으로만 만든 사용자-상품 이분 그래프에서 이웃 표현을 전파한다.
특성 변환과 비선형 활성화를 생략한 추천용 GNN이다.
BPR-MF와 같은 BPR 손실·임베딩 차원·음성 샘플링을 기본으로 맞춘다.
1·2·3층을 검증 집합에서 비교한다. 그래프를 쓴다고 정확도가 반드시 높거나 편향이 반드시 커진다고 전제하지 않는다.

### XSimGCL: 그래프 대조학습 효과 비교

노이즈를 더한 표현과 층 간 대조학습을 사용하는 그래프 추천 모델이다.
같은 노드의 표현이 작은 교란에도 일관되도록 학습하며, 표현의 분포도 조정한다.
LightGCN과 비교해 비인기 상품 노출과 정확도의 변화를 확인한다.
논문이 보고한 인기 편향 완화는 이 Automotive 데이터에서 확인할 **가설**이다.
XSimGCL은 자기 자신의 초기 임베딩을 최종 평균에 포함하는지 등 LightGCN과 세부 구현이 다르므로,
둘의 차이를 대조 손실만의 인과 효과라고 표현하지 않는다. 필요하면 대조 손실을 끈 XSimGCL도 보조 실험한다.

### 선택 이유와 최근 연구의 역할

이 조합은 **개인화 → 그래프 전파 → 그래프 대조학습**으로 비교 축을 설명하기 쉽다.
LightGCN·XSimGCL 자체를 최신 모델이나 현재 SOTA라고 부르지는 않는다.
2024–2025년 편향·재현성 연구와 2025년 이후 공개 벤치마크도 확인했으며,
이번 연구 질문과 제공된 ID 중심 데이터에 맞는 비교를 우선했다.
새 논문의 결과를 Automotive에서 재현된 성능으로 인용하지 않는다.

현재 상품 수가 248,186개이므로 EASE 같은 밀집 item×item 방법은 우선 제외한다.
이 크기의 float32 밀집 행렬 하나만 약 246 GB(약 229 GiB)가 필요하며, 실제 해법에는 추가 메모리가 든다.
차종·텍스트 기반 모델은 해당 특징 파일이 온 뒤 재정렬 실험에서 사용한다.

## 3. 고정 평가 조건

- 입력: 전달받은 5-core 날짜 분할 그대로. train에 다시 5-core를 적용하지 않는다.
- 학습: train만. 사용자 수 599,742, 상품 수 248,186.
- 설정 선택과 early stopping: valid만. test 점수로 설정이나 모델을 고르지 않는다.
- 최종 test: 모든 설정을 고정한 뒤 평가. train+valid 재학습은 현재 회의 합의대로 사용하지 않는다.
- 후보: 전체 학습 상품. 검증은 seen_for_valid, 테스트는 seen_for_test로 이미 본 상품을 제외한다.
- seen_for_test에 valid 이력을 넣는 것은 과거 관측 상품 마스킹이며, 검증 상호작용으로 모델을 학습하는 것이 아니다.
- 모든 모델은 같은 후보·정답·사용자 집합으로 비교한다. 일부 음성 상품만 뽑는 평가 점수와 섞지 않는다.
- 그래프·인기도·사용자 활동 그룹은 모두 train만으로 구성한다.
- 날짜는 UTC 밀리초 타임스탬프로 확인한다. README의 날짜는 일 단위 요약이므로 자정 기준으로 재분할하지 않는다.
- 전 기간의 5-core는 날짜 분할 뒤 train의 사용자/상품 차수가 5 미만인 것을 허용한다.

## 4. 지표

주 지표: 사용자별 binary-relevance NDCG@10을 계산한 뒤 사용자 단순 평균.
정답이 여러 개면 IDCG에는 min(10, 정답 수)개를 반영한다.

- Recall@10: 사용자별 적중 정답 수 / 사용자별 전체 정답 수.
- Hit Rate@10: 상위 10개에 정답이 하나 이상 있는 사용자 비율.
- APLT@10: 추천 10개 중 비인기 상품 비율의 사용자 평균.
- ARP@10: 추천된 상품의 train 상호작용 수 평균.
- Catalog Coverage@10: 추천에 한 번이라도 등장한 상품 수 / 전체 학습 상품 수.
- 활동 그룹: train 기록 1–5개와 6개 이상.
- Mismatch@10: 차종 정보 도착 후 정의·알 수 없음 처리·분모를 확정해 추가한다. 미계산을 0으로 쓰지 않는다.

비인기 상품은 제공된 item_map의 popular=False를 사용한다.
train 상호작용 누적 80% 지점에서 리뷰 수가 같은 상품을 모두 인기군에 포함해
11개 이상을 인기 상품으로 분류한다. 따라서 실제 인기군 상호작용 비중은 약 81.48%다.

현재 기준선 결과의 CI는 사용자 평균에 대한 95% 정규근사 구간이다.
최종 모델 비교는 같은 사용자끼리의 지표 차이에 대한 paired bootstrap과 학습 seed 변동을 구분해 보고한다.

## 5. 실행 순서와 완료 기준

1. **완료:** 환경·데이터 계약 점검. 39개 검사 통과 및 입력 해시 기록.
2. **완료:** 전체 valid 사용자에 대한 Popularity. 상위 100개 후보와 사용자별 지표 저장.
3. **완료:** 세 모델의 CUDA 전용 학습기·전체 상품 평가·best/last checkpoint 구현.
4. **완료:** 세 모델 각각 전체 train 한 epoch, 전체 valid 평가, optimizer/RNG 저장·복원 후 업데이트 재현 검증. [GPU 점검 결과](GPU_REVIEW.md).
5. **다음:** valid에서 설정 확정 → 학습 seed 42·43·44 반복 → 최종 test 비교. 초기 50 epoch 예산의 첫 비교는 3–4시간, 탐색·반복은 여유 포함 12–16시간으로 계획.
6. 차종·텍스트 파일이 오면 같은 추천기에 순위 조정 추가: 원래 점수 / 인기 감점 / 텍스트 / 차종 항을 순차 비교.

사용자가 기존 Colab 잔액 사용과 로컬 부하 최소화를 선택했으므로, **학습은 Colab GPU에서 실행한다.**
CLI 인증과 실행·파일 전송·결과 회수 방법은 [Colab 실행 환경](COLAB.md)에 기록했다.
로컬 M3 Max의 전체 train 그래프 희소 연산·역전파 측정은 참고 기록으로 보관한다.
최적화 후 전체 epoch 실측은 BPR-MF 약 16.5초, LightGCN 3층 약 54.5초,
XSimGCL 3층 약 114.1초였다. 전체 valid 지표 집계는 모델별 약 6–7초였다.
장기 수렴과 seed 반복은 아직 미실행이며, 자세한 측정·범위·시간 예산은 [GPU 점검 결과](GPU_REVIEW.md)를 따른다.
자세한 조건과 측정 한계는 [학습 환경 점검](HARDWARE.md)에 기록했다.
Colab CLI는 기존 계정 CU를 사용한다. 새 구독이나 별도 Google Cloud 유료 GPU를 결제하지 않는다.
로컬 소규모 smoke 결과는 전체 데이터 성능표에 넣지 않는다.

첫 설정 후보: 임베딩 64차원, BPR 음성 1개, learning rate {0.001, 0.0005}, regularization {1e-5, 1e-4}.
이는 아직 튜닝하지 않은 시작값이다. 모델마다 같은 검증 탐색 예산을 배정하고 모델 전용 설정도 기록한다.
같은 하이퍼파라미터 한 세트만 적용한 결과를 충분히 튜닝된 공정 비교라고 표현하지 않는다.

## 6. 추가 데이터가 필요할 때의 계약

현재 폴더에는 `uid, iid, timestamp`, 원래 ID 매핑과 train 통계만 있다.
따라서 차종 추출·텍스트 유사도·차종 불일치 평가는 아직 시작할 수 없다.

- 사용자 차종: 원래 user_id에 연결. 추출 근거와 그 시점, 제조사·모델·연식, 확실하지 않음 표시 필요.
- 상품 적합 차종: parent_asin에 연결. 허용 차종·연식 범위와 범용 상품 여부 필요.
- 상품 텍스트: parent_asin, 상품명/설명 필요.
- 사용자 차종·텍스트 프로필에 valid/test 리뷰를 읽어 넣지 않는다. 검증에는 train 시점까지의 정보만 사용한다.
- 한 사용자가 여러 차를 가질 수 있고 리뷰에서 차종을 언급했다고 소유 차량이라고 단정할 수 없으므로 추출 품질을 별도 점검한다.
- 모르는 차종은 불일치로 간주하지 않는다. universal-fit과 incompatible, unknown을 구분한다.
- 재정렬은 저장된 상위 100개 후보로 시작하고, 후보 Recall@100과 후보 수 확대 효과를 함께 확인한다.
- Mismatch 감소는 동일 특징을 점수와 평가에 쓰므로 일부 기계적으로 생긴다. 실제 효과는 NDCG 변화도 함께 판단한다.
